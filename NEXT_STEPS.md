# ContractorQuote: next 30 days

This is a short, practical checklist. The goal for this month is to **learn from real builders**, not to build more. Full background is in [`HANDOVER.md`](HANDOVER.md).

## Week 1: finish the launch checks

- [ ] On a real **iPhone (Safari)**: run the homepage example (40 h × £30, 20% burden, £800 materials, £500 subcontractors, £60 other, 10% overhead, 25% margin).
  - Check that the price is **£4,106.67**.
  - Save the quote as a PDF.
  - Check that it fits on one page and shows **no** costs, profit or margin.
- [ ] Do the same on a real **Android phone (Chrome)** and on a **desktop browser**.
- [ ] Print the blank **quote template**, or save it as a PDF. It should fit on one page.
- [ ] **Search Console:** note the sitemap status and how many pages are indexed. Don't resubmit.
- [ ] **Cloudflare Web Analytics:** for each of the two entries, write down its hostname, its snippet token and its last 7 days of visits.
  - The site's token ends `…587ac1`.
  - **Don't delete either entry.**
- [ ] Optional: update the GitHub repository description, which still describes the old proofreading tool. Use the gear icon next to "About" on the repository page.

## Week 2: reach real builders

- [ ] Make a list of 5–10 places where UK builders and small contractors talk online, such as trade forums, Facebook groups, Reddit communities and local business groups. Read each one's rules on self-promotion first.
- [ ] Write a short, honest post: "I've built a free pricing and quote tool for UK builders, with no sign-up. Would you try it on a real job and tell me what's confusing?"
- [ ] Post in 2–3 of those places. Reply to every response.
- [ ] Ask 3–5 builders you know, or can contact directly, to try it.

## Week 3: watch people use it, and collect feedback

- [ ] Ask each tester to price one real or recent job and make a quote.
- [ ] Ask them the same questions each time:
  1. What was confusing?
  2. What was missing?
  3. Would you send this quote to a customer? Why or why not?
  4. What do you use today instead?
- [ ] Write every answer in one simple list, such as a spreadsheet or a notes file: who said it, what they said, and the date.
- [ ] **Don't change the site yet**, unless someone finds a real bug such as a wrong number, a broken page or the quote not printing.

## Week 4: decide what to improve

- [ ] Group the feedback. Which issues came up **more than once**?
- [ ] Pick the **one or two** most repeated issues and write each as a small, clear task.
- [ ] Give each task to your coding assistant as its own branch and pull request. Point it at `HANDOVER.md` first.
- [ ] Check Search Console and analytics once this week, and note any change.
- [ ] Monetisation: **not yet.** Revisit only once people are using the site regularly or asking for more.

## Every week

- [ ] Glance at Search Console and Cloudflare analytics once. There's no need for daily checks.
- [ ] Keep the feedback list up to date.
